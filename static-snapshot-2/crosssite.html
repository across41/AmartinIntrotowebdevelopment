More about Cross-Site Scripting

Cross-site Scripting is malicious script that allows hackers to insert into a server. It allows hackers to get many victims as they are able to execute attacks on big companies and do it in ways that manipulate many people. Once a hacker has gotten through, they are able to act as the user and gain access to the users’ sensitive data. There are many different types of Cross-Site Scripting, reflective, stored and DOM-based. Each one of the methods are used depending on what the hacker is trying to use to obtain the users data. Reflected XXS is when a malicious script is placed within a website and convinces the user into executing it like by clicking on a link. We are seeing this commonly now with phishing attempts. Phishing attempts are sometimes extremely hard to recognize, we see them often mimic emails you would usually get. For instance, if you typically get emails from Netflix when you need to update your payment details hackers will change slight things like using a .com email instead of a .org email in order to trick people into thinking they are actually updating their information with Amazon. Stored XXS is where the attacker injects code into a web application. When the user loads the page that is when the attack is triggered. DOM-Based XXS is where a hacker gains access to the users side by manipulating the Document Object Model of a page. This type of scripting is the hardest to do but also the hardest to fix.

Real-word Cross-Site Scripting example

In 2015 a group of hackers were able to install keyloggers into the POS system at Wendy's. The hackers were able to breach from an XSS vunerabilty through a customer feed back form. Keyloggers are a type of malware that keeps track of your keystrokes as you type. The hackers were able to take this and gain over 5.5 million payment cards. Wendy's was then faced with a class action lawsuit that costed $50 million dollars in setllement. It showed how just a small crack in the system can open up hackers to have so much more information, putting so many at risk.

Prevention Methods

After seeing how much damage came from a small error in a customer feedback form, it is important to make sure that companies are constantly updating their code to prevent these things from happening. A helpful resource companies can use to reduce their vulnerability to XSS attacks is this XSS Cheat Sheet by Adobe. It outlines coding best practices to minimize exposure to XSS threats and should be reviewed regularly by web development teams.
